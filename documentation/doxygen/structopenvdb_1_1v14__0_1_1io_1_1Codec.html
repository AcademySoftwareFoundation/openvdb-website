Detailed Description

Abstract base class for grid I/O codecs.

A codec encapsulates the serialization and deserialization logic for a specific grid type (or family of grid types). The I/O subsystem selects a codec by name at runtime, calls createData() to allocate per-operation state, and then dispatches to the appropriate read or write methods.

Codecs must be stateless: all mutable per-operation state is stored in a CodecData object (see above) that is created fresh for each grid read or write. This ensures that a single registered codec instance can safely handle concurrent I/O operations.

Implementing a new codec
  1. Declare the codec struct, deriving publicly from Codec (or from a convenience intermediate that already handles topology, if one exists for the grid family in question):
    struct MyCodec : public io::Codec { ... };

    A grid is read in four phases: beginRead() => readTopology() => readBuffers() => finishRead().

    For non-instance grid reading, only beginRead and finishRead are guaranteed to run. A topology-only read will skip the readBuffers() phase for example. Compute tasks may continue asynchronously across phases, the codec owns that work and is responsible for starting and ending it.

◆ beginRead()

virtual void beginRead ( CodecData & ,
const ReadOptions & ,
ReadDiagnostics &  ) const
inlinevirtual

Begin a read. Called by the I/O layer once before the first phase of every read of a grid, for every read mode, after the metadata and the transform are read. It is not called for instances, which have no phases.

This is the place to start work that later phases use, for example a thread pool, or to choose a strategy from the read options, the metadata and the transform. Until finishRead() returns the caller does not touch the tree of the grid. If this throws, no other phase is called, including finishRead(), so the destructor of the CodecData must release anything started here. The default implementation does nothing.

◆ createData()

virtual CodecData::Ptr createData ( )
pure virtual

Allocate per-operation codec state, including the target grid.

This is the only pure-virtual method. Implementations must create a concrete GridBase subclass appropriate for the codec, store it in CodecData::grid, and return the CodecData (or a derived subclass carrying additional state). The returned object is passed by reference to every subsequent read or write call for the same grid.

Returns
A fully initialized CodecData whose grid field is non-null.

◆ finishRead()

virtual void finishRead ( CodecData & ,
const ReadOptions & ,
ReadDiagnostics &  ) const
inlinevirtual

Finish a read. Called by the I/O layer after the last phase of every read of a grid, for every read mode and whether or not readTopology() and readBuffers() were called, so work that a codec started in an earlier phase has one place to be joined. It is not called for instances, which have no phases.

Until this returns the caller does not touch the tree of the grid. It may read and change the metadata and the transform. An error from work started in an earlier phase is thrown from here, on the calling thread. The default implementation does nothing.

◆ readBuffers()

Deserialize all voxel-value buffers from is into the grid held by data.

The default implementation is a no-op. Override to populate leaf-node value buffers after topology has been established. When options.readMode is ReadMode::TopologyOnly this method will not be called by the I/O layer, so implementations may also guard against that mode internally for safety. If options.clipBBox is non-empty, restrict the loaded data to the region that intersects it; if the codec cannot honour clipping natively, fall back to a post-process and record a warning via diagnostics. The size argument is the number of bytes occupied by the readBuffers data section, measured from the stream position at which this method is called, or -1 when the size is not known (a non-seekable stream, or a stream without grid offsets).
